# Project memory

## Product intent & audience

- Приложение с функцией «алтарь» (altar_entries) и пользовательскими аватарками.
- Пользователи загружают изображение с устройства для своего аватара; важна устойчивость загрузки при ошибках хранилища.

## Brand personality & voice

- Тон: практичный, понятный, дружелюбный; сообщения на русском, конкретные и без техжаргона («Так её увидят на алтаре»).

## Visual design & UX direction

- Форма загрузки в боковой панели записи, кнопка «Файл».
- Предпросмотр аватара: крупный круг, подпись-объяснение, кнопка убрать картинку.
- Поведение: авто-сжатие/обрезка скрыты от пользователя; понятные сообщения об ошибках и лимитах.

## Decisions, constraints & rationale

- Стек: Vite + React, Supabase (Storage + таблица `altar_entries`, поле `avatar_url`).
- Создан публичный bucket `avatars` с политиками на чтение и загрузку.
- Изображение обрабатывается через скрытый `<canvas>`: центральный кроп в квадрат 128×128, кодирование `image/webp` (фолбэк `image/jpeg`, качество 0.82).
- Лимит исходного файла: 5 МБ.
- Поток: попытка загрузки сжатого файла в Storage → при любой ошибке фолбэк на `data:image/...` URL прямо в `avatar_url`. Rationale: загрузка не падает, даже если Storage/политики недоступны.

## Open questions & assumptions

- Предполагается, что RLS/политики `avatars` корректны для публичного чтения и загрузки; при изменении схемы Storage фолбэк на data URL остаётся страховкой.
- WebP поддерживается большинством браузеров; JPEG-фолбэк покрывает старые.
